## 环境与命令

Pi 直接加载 TypeScript ESM 源码，没有独立服务、编译产物或 build 步骤。包声明 Node.js 至少 22.19，开发基线为 Node.js 24、Pi 1.5.0、macOS，不代表声明范围中的所有环境都已测试。

```bash
npm ci --ignore-scripts
npm run check
```

`npm ci` 按锁文件安装开发依赖，忽略依赖安装脚本。coding-agent 和 TypeBox 是宿主提供的 peerDependencies，具体开发版本在 devDependencies；不要把它们打包成另一份运行时宿主。

```bash
# 类型检查，不输出 JavaScript
npm run typecheck

# Node 内置测试运行器执行全部测试
npm test

# 只运行单个模块
node --experimental-strip-types --test src/memory-store.test.ts

# 检查分发文件，不生成 tarball、不上传
npm pack --dry-run
```

`npm run check` 先做类型检查，再运行全部测试。没有独立 lint、formatter 或 build 命令。按名称筛选测试时，先在当前测试文件中查找真实用例名称。

## 源码导航

| 模块 | 职责 |
| --- | --- |
| `src/memory-extension.ts` | 三个前台工具、命令、开关、context 注入和后台调度 |
| `src/memory-schema.ts` | Markdown 写入工具参数与作用域类型 |
| `src/memory-store.ts` | 项目定位、活动文件读写、哈希冲突、历史、锁与原子替换 |
| `src/memory-search.ts` | 词法检索、文件列表和紧凑索引上下文 |
| `src/memory-dream.ts` | 独立模型循环、来源工具接入、工具白名单、预算和取消 |
| `src/memory-sources.ts` | 同项目原生历史只读发现、分支与上下文编辑、来源搜索与精确分页读取 |
| `src/memory-schedule.ts` | 项目级持久轮数、最新 leaf 去重、任务租约与代次确认 |
| `src/memory-observations.ts` | 已完成交互的有序提交、锁释放事件唤醒与失败保留 |

测试与相应模块就近放在 `src/*.test.ts`，合成 fixture 放在 `test/`，不进入分发包。涉及 Pi API 时核对当前开发依赖内的文档和类型，特别是 `context`、`agent_settled`、投影与模型注册表接口，按当前 API 核对，不凭印象改动。

## 自动化检查应覆盖什么

| 层面 | 主要断言 |
| --- | --- |
| 存储 | 项目与全局隔离、路径和 identity 校验、明文 Markdown、哈希冲突、历史保留与容量、锁、取消和原子替换 |
| 检索与索引 | 英文词、汉字和日文假名双字检索、无 query 列表、只注入 MEMORY.md、不自动注入命中正文、预算与临时性 |
| 前台接口 | 三个工具 schema、默认值、轻量用途与自主选择提示、无固定正文模板，保留工具操作说明；行范围内 Unicode 码点分页与 8 KiB 页上限、长单行读取、完整 JSON 输出、全局自主写入、项目信任和仅元数据写入回执；唯一 `/memory` 命令的空参数用法、原话转交与忙时 follow-up，无旧命令别名或管理子命令 |
| 后台调度 | 新完成前台交互不依赖写笔记，跨会话累计 8 次未处理轮数后自动领取；最新 leaf 重复通知去重、只读启动不建库、关闭自动调用仍记录、两个启动开关独立，无手动整理或运行时切换入口 |
| 调度并发与恢复 | 多运行者不重复领取有效租约，成功只确认领取代次，期间新工作保留；交互计数遇锁保留顺序与原始身份、释放后补记且不重复，同 session 模块重载仍共享 FIFO，新旧观察不能倒退最新 leaf 或提前触发整理；切换不从旧上下文启动新任务，已开始的任务则跨运行时替换继续执行且不访问旧上下文；前台工作不取消整理，成功确认后检查后续工作；退出仍有内存观察时明确警告；失败、取消不丢已落盘的待处理状态，过期租约可重新领取，损坏状态不重置为空 |
| 后台来源 | 同项目头 cwd 校验、跨会话与压缩前原文、当前活动分支和历史最后父链、上下文删除与替换、稳定 ID、完整可见文本哈希与 8 KiB Unicode 码点分页；不读 thinking、签名、图片、系统和自身记忆结果 |
| 来源扫描边界 | 宿主根目录与自定义会话目录、当前未落盘会话、精确 ID 不依赖搜索页、空页仍可继续、预算和警告、继承条目重复标识、安全路径、损坏与超限拒绝、不改写原始历史 |
| 后台模型循环 | 同一所选模型与注册表、只允许项目记忆和两个来源工具、预算、冲突、取消及部分提交保留 |
| 合成集成闭环 | 脚本模型从未写入笔记的历史反馈创建首份记忆，跨会话回读来源纠正旧假设、合并归档重复笔记并修复索引；新会话读取落盘 Markdown，不证明模型判断质量 |
| 真实 CLI | 从包清单加载扩展，离线检查启动 flags 与空 `/memory` 用法，不发模型请求；长活 RPC 配合合成 provider 检查空闲请求、忙时 follow-up、工具写入和新会话索引召回，不请求真实模型提供商 |

这个表是维护时的检查范围，不是某次执行全部通过的回执。交付时应报告实际命令和结果，以及尚未覆盖的行为。

历史来源测试只在临时宿主目录内写合成 v3 会话，包括跨项目、分支、压缩与上下文编辑的反例。扫描前后比较原始文件内容及目录清单，确认不会迁移、补写或生成会话文件；缺失根目录保持缺失。调度测试应让不同会话或独立调度调用共享同一项目存储，覆盖新实例读取已落盘轮数，而不只测试内存中的累计。

脚本集成至少包括两种起点：已有待纠正笔记，以及只有历史反馈、尚无 Markdown 的项目。前者验证按历史 ID 读取后修订与归档，后者验证无需前台 memory_write 也能创建笔记和索引。脚本预先指定模型响应，只证明能力与数据流，不证明真实模型能自主选对经验。

### 隔离要求

单元测试使用临时目录和合成来源，不读取真实用户会话、日常记忆库、凭证或私有路径。模型循环测试用可控制的模拟响应，不应为普通测试调用付费模型。

真实 CLI 测试使用独立 Pi 配置、临时项目、临时 `PI_MEMORY_DIR`、离线模式、禁用其他扩展和资源、`--no-session`。空命令检查不启动模型；RPC 工具闭环仅额外加载测试用合成 provider，不请求真实模型提供商。仅设置 `PI_MEMORY_DIR` 不足以隔离宿主配置、凭证或网络。测试不能为了获得一条来源而扫描真实会话文件。

临时目录先规范化真实路径，避免 macOS 的 `/var` 与 `/private/var` 别名造成 identity 不一致。并发测试必须明确等待机制和清理方式，不依赖任意延迟碰运气。

### 文档与包检查

文档改动后检查本地 Markdown 链接及标题锚点，按注册的工具 schema 校验 JSON 示例，确认占位哈希没有被描述成可直接执行的值。目录示例应与当前实际布局一致。

`npm pack --dry-run` 的清单应包含中英文 README、AGENTS.md、docs 下的中英文用户文档及其本地链接目标，不包含测试和 fixture。AGENTS.md 保持单份中文维护指令。工具参考若链接到源码，也要确认源码进入包。打包检查不能代替行为测试或真实模型效果评测。

### 文章对齐 review

本地维护工作区若有 `references/components-of-agent-memory/`，其中保存文章图文快照。该目录不进入 Git 或 npm 包，因此全新克隆不含它。若缺失，查阅原始文章并明确离线材料或读图覆盖的限制，不能宣称已检查缺失的快照。目录存在时，先读该目录 README，运行 `python3 references/components-of-agent-memory/verify-archive.py` 核对保全文件，再读完整 `article.md` 和其中的 15 张内容原图。文本、alt 和哈希校验都不能代替实际看图；无法读取某张图时，应明确未覆盖，不能宣称完成图文审阅。原文和图片属于第三方内容，不受本项目 MIT 授权覆盖。

对照 [design 中的文章理解](design.zh-CN.md#与参考文章怎样对应)检查当前代码，区分前台用途指导与后台维护任务、来源与笔记、能力与真实模型效果。架构图的箭头不是强制流水线，具体任务的指令优化、预算和图谱规模不是通用最低要求。报告应注明取样、实际读图范围、代码与测试范围；文章 benchmark 不能作为扩展效果的验证结果。

## 手工验收

以下步骤需要另行决定是否调用模型。它们不是已完成的 UI 或效果验证。

在独立测试项目中显式指定测试记忆目录：

```bash
PI_MEMORY_DIR=/absolute/path/to/scratch-memory \
  pi -e /absolute/path/to/pi-memory --pi-memory-no-dream
```

这只隔离记忆目录，仍使用正常 Pi 配置和提供商凭证，正常对话仍可能联网。自动 dreaming 先关闭，避免在检查其他功能时意外产生额外请求。不要把 scratch 路径指向真实库。

建议按以下顺序验收：

1. 输入 `/memory <自然语言说要记住的一件事>`，用合成反馈让 Agent 自主新建 Markdown，再维护索引，确认命令处理器没有直接生成笔记。空 `/memory` 应只显示用法、不调用模型；前台忙时提交保存请求，应在当前运行结束后作为 follow-up 处理，而不是中断或 steering。
2. 用自然语言让 Agent 通过 `memory_search`、`memory_read` 查找和读取笔记；检查索引很小，详细笔记只有按需读取时才进入上下文。这些是模型工具，不是扩展管理子命令。
3. 重开同项目会话，确认共享记忆；换独立项目检查隔离，再显式让 Agent 查看全局记忆。
4. 先读取哈希，再从另一写入者修改同一文件，确认旧哈希被拒绝，且不会丢失新内容。
5. 让 Agent 归档普通笔记，确认活动搜索移除、旧正文保留、索引需单独维护，MEMORY.md 不能归档。
6. 用 `--pi-memory-no-recall` 重启，确认工具仍能读写；不带该参数重启后恢复索引召回。不要把 recall 开关当成 dreaming 开关，两者没有运行时切换命令。
7. 获得额外模型调用授权后，不带 `--pi-memory-no-dream` 重启，在累计至少 8 次未处理前台交互后观察自动整理、额外请求、项目范围和来源边界；分别检查有旧笔记需纠正，以及仅有合成历史反馈、没有笔记的情况。没有手动 dreaming 命令。
8. 在后台运行时输入新消息、启动前台运行、导航会话树、fork 或切换会话，确认整理继续使用原项目和已捕获的发起会话分支，不访问已失效的旧运行时。再累计八次完成的交互，检查本轮成功后能接续下一轮。退出或显式重载扩展时，检查取消与已完成写入保留，不期望整批回滚。
9. 在多个独立测试会话中累计前台交互，检查计数跨会话保留；用 `--pi-memory-no-dream` 关闭自动整理期间不发后台模型请求，但不带该参数重启恢复后待处理轮数仍在。不要期望退出 Pi 后继续执行。

### 交互式与长活 RPC 的验收边界

非空 `/memory` 在交互式 Pi 中使用，自动化验收用保持进程存活并持续消费事件的 RPC 客户端。Pi 1.5.0 的一次性 `pi -p '/memory ...'` 存在宿主 preflight 与扩展 `void sendUserMessage` 异步请求之间的竞态，不作为非空命令的支持验收路径，也不在扩展中补丁式绕过。空 `pi -p '/memory'` 只检查用法，不涉及后续模型运行。

合成 CLI/RPC 检查位于 `src/memory-cli.test.ts`，可单独执行：

```bash
node --experimental-strip-types --test src/memory-cli.test.ts
```

需要模型的 RPC 验收应明确以下顺序和断言：

1. 在隔离环境启动长活客户端，先订阅事件并设置完成超时，再提交非空 `/memory`。忙时场景先启动普通任务，等实际流式事件后再提交保存请求，不靠固定延迟猜测。
2. `/memory` 的 RPC `handled` 只表示命令处理器返回，不是保存完成。命令自身未启动普通 prompt 运行，但会通过 `sendUserMessage` 另行触发前台运行；继续消费其事件，直到这次后续运行的 `agent_settled`。空 `/memory` 不应等待这个模型完成事件。
3. 检查保存请求保留用户原话、模型确实调用 `memory_write`、正文与索引已落盘。忙时还要确认原任务先结束，保存请求随后执行，没有 steering 或中止原任务。模型声称保存或仅收到 `handled` 都不够。
4. 等保存运行完成后，用 `newSession` 建立同项目的新会话，再发一条不含待记内容的普通问题，检查新请求收到落盘 `MEMORY.md` 的临时注入。不要复用旧消息当作跨会话召回证据。

合成 provider 只验证该事件和工具流程，不能算真实模型效果或人工 TUI 验收。真实 provider 的验收也需保留相同完成边界，另行取得调用授权，使用独立临时 Pi 配置、仅供测试的凭证、合成材料和独立记忆目录，并记录实际结果。

自动 dreaming 的计数与边界优先由模拟模型测试验证。真实模型试验需单独记录输入材料、模型与版本、请求成本、完成写入和失败情况，不能用一次成功整理推断普遍收益。

## 如何报告验证结果

分别报告类型检查、单元测试、真实 CLI 加载、人工 TUI 验收和真实模型记忆效果。前三者通过，只证明已断言的程序行为，不证明模型会保存正确知识、读对笔记或得到更好的任务结果。

没有共同任务的对照实验，就不声称复现 Anthropic 文章中的提升。公开效果结论需要可复现的任务集、无记忆基线、模型与预算、来源和结果记录。

安装到个人配置、全局配置修改、模型调用、提交、推送和发布都不是普通检查的默认授权。`npm pack --dry-run` 不发布，也不证明拥有 npm 同名包。
