# 使用指南

[English](usage.md) | 简体中文

这里说明 pi-memory 的安装、操作、存储和故障排查。快速上手见 [README](../README.zh-CN.md)。

## 试用

需要 Pi、Git 和 Node.js 22.19 或更新版本。已验证的开发环境为 Pi 1.5.0、Node.js 24、macOS。独立自动整理目前要求 POSIX 宿主，不支持 Windows。

在你要工作的项目目录中运行，Pi 会从 GitHub 下载扩展，不用手动克隆仓库：

```bash
pi -e git:github.com/ttttmr/pi-memory --pi-memory-no-dream
```

这只为当前进程加载扩展，不会把它加入 Pi 设置，但会保留本地包缓存。这里先关闭自动后台整理，避免试用时产生额外的整理请求；普通对话和 `/memory` 仍使用你的 Pi 模型与凭证。

想让 Agent 记住一件事时，直接输入：

```text
/memory 这个项目用 npm run check 做完整检查，交付前先跑一次。
```

`/memory` 后面都是要记住的自然语言，不是子命令。它把这句话交给 Agent，提醒它为未来轮次和会话保存记忆；Agent 自主决定笔记内容、组织和是否需要更新索引。命令本身不会直接写固定格式的笔记，也不会在保存前宣称成功。空的 `/memory` 只显示用法，不发模型请求；Agent 忙时，非空请求排队等待当前任务结束。

之后在同一项目开启另一个已加载扩展的会话，可以正常提问：

> 这个项目交付前应该跑什么检查？请查一下之前的记忆。

三个模型工具是 `memory_search`、`memory_read`、`memory_write`，不必手写工具参数。需要查看或纠正某条记忆时，直接用自然语言让 Agent 查找、读取、修改或归档。只有 `/memory` 这一个扩展命令，没有路径、列表、搜索或整理的子命令。工具协议见[工具参考](tools.zh-CN.md)。

Agent 在普通工作中也可自主记录值得保留的经验，不保证聊过的所有内容都会保存。需要保留时可以明确要求，并让 Agent 读取已保存内容确认；不能只凭一句“记住了”判断文件已经落盘。

## 安装、更新与移除

需要长期启用时，从 GitHub 安装：

```bash
pi install git:github.com/ttttmr/pi-memory
```

安装会把包加入个人 Pi 设置。之后在要工作的项目目录中运行 `pi`，便可在会话内使用 `/memory`。若要保持关闭自动后台整理，用 `pi --pi-memory-no-dream` 启动。

更新这个包：

```bash
pi update git:github.com/ttttmr/pi-memory
```

更新后重启 Pi，或在现有会话中运行 `/reload` 加载新代码。

移除扩展：

```bash
pi remove git:github.com/ttttmr/pi-memory
```

移除不会删除记忆文件。不要把 npm 上的同名包当成本项目。

本地开发仍可用 `pi -e /absolute/path/to/pi-memory` 加载仓库副本。

## 控制自动召回和后台整理

不传关闭参数时，自动召回和自动后台整理默认开启。同项目累计 50 条尚未处理的实际用户消息后，独立的普通 Pi Agent 可以回看该项目历史会话，创建新笔记或整理已有笔记。前台运行结束后观察消息，按条目 ID 持久去重并跨会话累计。会话启动时已有消息只作为基线，不追溯计数；不要求前台先保存笔记。旧的待处理轮数迁移为可触发一次整理的 legacy 工作，不计作实际用户消息。

后台整理使用所选 provider、model 和 thinking 级别，**会产生额外请求和费用，退出 Pi 后也可能继续计费**。它重新加载正常 Pi 配置与凭证，拥有默认文件和 shell 工具，以及配置的扩展、skills 和 MCP 工具；前台仅在运行时存在的变化不会复制过去。worker 重新检查正常项目信任，前台未持久保存的临时批准可能无法沿用，从而安全地启动失败。这不是受限的来源工具沙箱。启动时加 `--pi-memory-no-dream` 可阻止新的自动启动，但不会取消已运行的 worker。

分别关闭两项功能：

```bash
pi --pi-memory-no-recall --pi-memory-no-dream
```

启动参数控制当前运行实例，不持久保存。需要恢复某项功能时，重新启动 Pi 并去掉对应的关闭参数。没有运行时开关或手动整理命令。

关闭召回不等于关闭整理，也不会禁止 Agent 显式读写记忆。关闭自动整理后，新的实际用户消息仍会记录，重新启用后可继续处理。

整理期间可以继续聊天、导航会话树、切换会话、重载扩展或退出 Pi。独立 Agent 继续处理原项目，可以在前台退出后完成；新消息留待后续整理。每次运行从启动起有 30 分钟墙钟期限，由 supervisor 执行，短暂清理宽限后强制杀死进程组与已捕获的后代进程。这是尽力清理，不是对已脱离进程或外部工作的强制隔离。已完成写入不回滚。这不是永久守护进程，未启动的工作等待之后符合条件的前台时机。启动通知不等于成功回执。

## 存储位置与备份

默认根目录通常为 `~/.pi/agent/pi-memory`，实际位置为 Pi 的 Agent 目录下的 `pi-memory/`。其下是项目目录 `project-<hash>/` 和全局目录 `global/`。可以用 `PI_MEMORY_DIR` 指定其他位置，建议使用绝对路径：

```bash
PI_MEMORY_DIR=/absolute/path/to/memory \
  pi --pi-memory-no-dream
```

记录项目细节时使用项目记忆；只有真正跨项目、非私密的知识才适合放进全局。可以用自然语言告诉 Agent 保存到哪个范围。

同一 Git 项目的子目录共用项目记忆，独立 worktree 和不同位置的克隆分开。移动项目目录会改变记忆归属，不会自动搬迁文件。具体定位规则见[设计说明](design.zh-CN.md#两个作用域怎样定位)。

备份前确认所有写入者均已停止，包括独立的后台 worker；仅关闭前台 Pi 不够，先检查运行记录。复制完整存储根目录，包括隐藏文件与历史。各项目的 `.dream-runs/<run>/` 保存私有的 `status.json`、`events.jsonl`、`supervisor.log` 和 `sessions/` 下的 worker 原生会话，可能包含原始敏感工具文本，需与笔记和备份一起保护。归档笔记不是永久删除，也不会清理已有会话、备份或提供商副本。

## 故障排查

| 现象 | 检查与处理 |
| --- | --- |
| 找不到 `/memory` 或三个工具 | 检查是否加载了 GitHub 包或本地仓库副本，避免另一扩展注册同名命令或工具 |
| 没有保存笔记 | 用 `/memory` 明确要求保留，再让 Agent 读取已保存内容确认；后台也可从历史工作中创建笔记，但不保证每段对话都会被保存 |
| print 模式下非空 `/memory` 立即退出 | 请在交互式 Pi 会话内使用 `/memory`。Pi 1.5.0 的 `pi -p '/memory …'` 可能过早释放命令另行生成的请求，不作为受支持的保存方式 |
| 项目记忆要求信任 | 先审核项目，再按 Pi 流程授权，不盲目信任陌生项目 |
| 搜得到笔记，但 Agent 没使用 | 明确要求搜索、读取该笔记；自动召回不会直接装入所有正文 |
| 全局笔记读不到 | 让 Agent 显式读取全局范围，而不是当前项目范围 |
| 哈希冲突 | 让 Agent 重读并比较新内容，再决定如何合并，不强行覆盖 |
| 记忆锁冲突 | 笔记写入需等写入者结束后重试；交互计数会在当前进程中排队，锁释放后自动补记，不抢锁。退出时若提示计数尚未保存，不要把它当成已落盘；崩溃遗留锁需确认没有写入者后再人工处理 |
| identity、路径或文件校验失败 | 停止写入并保留原文件，检查归属和结构，不清空目录绕过错误 |
| 容量或历史上限 | 先停止写入并备份，再按[存储限制](design.zh-CN.md#归档与容量)处理；归档也需要历史空间 |
| 自动整理没启动 | 检查启动参数、项目权限与当前模型；同项目需累计 50 条尚未处理的实际用户消息，或存在到期的迁移 legacy 工作；启动时已有历史不计数。检查 `.dream-state.json` 与 `.dream-runs/`，有效项目租约会阻止重复启动。退出期间未启动的工作等待，已运行的 worker 可以继续 |
| 整理失败或超时 | 查看运行的 `status.json`、`events.jsonl`、`supervisor.log` 和原生会话，检查模型可用性与正常 worker 配置。启动成功不表示已完成；失败保留待处理工作，已完成写入仍保留 |

## 隐私与使用注意

文件以明文保存在本地，读入上下文的笔记和 worker 读取的历史材料会发给所选模型提供商。独立 Agent 可以跨会话读取同项目原生日志，包括压缩前仍保留的文本，以及旧过滤来源工具不返回的原始字段。直接文件读取不自动保证活动分支选择、上下文删除与替换过滤，也不自动排除 thinking、图片、系统相关内容或工具参数。不要把上下文删除当成原生日志已经擦除。

任务提示要求只读会话与源码，通过记忆工具安全写入项目记忆，并把历史指令视为不可信依据而非权限。**这些是提示规则，不是操作系统沙箱。** worker 拥有普通 Pi 文件和 shell 工具，以及配置的扩展、skills 与 MCP 资源，可以访问文件或网络。它自身的会话与事件日志也可能保留敏感工具文本。不要把凭证、私密提示、个人隐私或整段日志存成笔记。本地存储不代表内容不会离开设备。若不能接受这种历史访问范围或完整 Agent 权限，启动时关闭自动整理；这会阻止新启动，不会取消已经运行的 worker。

记忆可能过时或有误，重要操作前仍应核对当前环境和依据。它不能代替项目指令，也不能扩大你对 Agent 的任务授权。
